Fieldnote: inspections that survive the basement

Building surveyors filled 60-question forms on paper, then retyped them at night. I designed and built the app that replaced both, offline first.

Role
Design engineer, lead
Team
2 engineers, 1 product manager
Timeline
January to September 2025
Stack
TypeScript, IndexedDB, Web Components
Context Constraints Process Decisions Design and code Results

Context

Halden Surveys inspects 1,200 buildings a year. Each visit produced a paper form, a camera roll and an evening of retyping. Reports reached clients three days later, and one in twenty had a missing answer.

The brief was a tablet app. The real job was to make the paper unnecessary without asking 40 surveyors to change how they walk a building.

Constraints

  • No signalBasements, stairwells and plant rooms. The app can never wait for a server.
  • Gloves onLarge targets, no hover, no long press, one free hand at best.
  • Fixed reportThe insurer sets the report layout. The app has to produce it to the line.
  • Old tabletsFour-year-old Android devices with 3 GB of memory.

Process

I spent the first two weeks on site with six surveyors, then tested a paper version of the room checklist before writing any code. The form engine came third: questions as data, so the insurer's format could change without a release.

Decisions

  1. 01

    Every tap saves

    No Save button and no draft state. An answer exists the moment it is given, on the device first.

  2. 02

    Sync state is always on screen

    A small status in the header, never a modal. It names the data, not the network: saved on this tablet, syncing, synced.

  3. 03

    Questions are data

    The 60 questions live in a JSON schema the product manager edits. The app renders it, so a new insurer rule ships the same day.

Design and code

The status and the sync queue were designed together. Each visual state maps to exactly one queue state, so the interface never claims more than the data knows.

type SyncState = "saved" | "syncing" | "synced" | "conflict";

// One label per queue state: the header says exactly what the data knows.
const label: Record<SyncState, string> = {
  saved: "Saved on this tablet",
  syncing: "Syncing",
  synced: "Synced",
  conflict: "Two answers: choose one",
};

Results

Same dayReports sent after the visit, down from three days.
0Inspections lost in nine months of use.
−35%Time per inspection, retyping included.
40 / 40Surveyors using it every working day.

We stopped retyping. That alone paid for the project.

Head of surveying, Halden Surveys
